## Approach
- **Parser** (`src/updates.ts`): `whatsNew(body): string[]` scans lines. It starts after a heading matching `/^#{1,6}\s*what'?s new/i` and collects `- `/`* ` bullets with the marker stripped. It stops at the next `#` heading, a line starting `<details` or `**Full changelog`. `plainNotes(body)` strips HTML tags and heading markers and trims the result. Both are pure, so they get table-driven unit tests.
- **Pending entry** (`src/updates.ts`): `saveWhatsNew(version, items, storage)` and `takeWhatsNew(runningVersion, storage)`. The second reads, clears and returns the items when the versions match, otherwise undefined. It uses the existing read/write helpers, which never throw. `FoundUpdate.install` calls save first, so the entry is saved before `downloadAndInstall`. `FoundUpdate` gains `whatsNew: string[]`, parsed once in `findUpdate`.
- **Panel** (`src/whatsNewDialog.ts`): a modal `<dialog class="settings update-dialog whats-new">` built the same way as `updateDialog.ts`: a title, a `<ul>` of the first 6 items, a "See all changes" link (`openUrl(releasePageUrl(v))`) and Close. `main.ts` calls `takeWhatsNew(APP_VERSION)` in the first window after the splash, before `startupCheck`, and shows the panel when there are items.
- **Dialog**: it replaces the `<pre>` with a `<ul class="update-notes">` when there are items, otherwise the plain-text fallback. A "See all changes" link sits under it. The CSS in `src/styles.css` reuses the sunken notes block.
- This adds no network use. The existing spec's "send nothing else" still holds.
