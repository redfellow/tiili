## Approach
- **Resolution (`src-tauri/src/repo.rs`)**: `find_repo` walks to the nearest `.git`. A folder: common dir is that folder. A file: parse `gitdir: <path>` (relative to the `.git` file's folder); if `<gitdir>/commondir` exists, the common dir is it resolved relative to gitdir and the pane is a linked worktree; otherwise the gitdir is its own repository. Any read/parse failure or missing target → today's behaviour (folder is repository, keyed by its path). `Repo` gains `key: PathBuf` (canonicalised common git dir, `dunce`-style stripping of `\\?\` on Windows or plain `std::fs::canonicalize` plus prefix strip) and `worktree: Option<String>` (branch from `<gitdir>/HEAD` `ref: refs/heads/…`, else the gitdir's last component). Name from the common dir: `X/.git` → `X`, `*.git` → stem, dot-named → parent name. `root` stays the worktree root for cwd purposes.
- **Tints (`tints.rs`, `lib.rs`)**: `PaneCwdEvent::new` passes `repo.key` instead of `root` for local panes. `RepoInfo` gains `worktree: Option<String>`.
- **Polling (`cwd.rs`)**: `report_polled` while an OSC 7 stands re-runs `find_repo` on the OSC 7 cwd (local only) and emits if it changed; `emit` dedupes so nothing new is sent when equal. Windows has no poll thread.
- **Chip (`src/paneChip.ts`)**: `placeLabel` appends ` › <worktree>` when `repo.worktree` is set (local only).
- **Remote (`src/remoteSnippets.ts`, `cwd.rs remote_repo`)**: snippets take the first `worktree` line of `git worktree list --porcelain`, falling back to `--show-toplevel`; `remote_repo` strips a trailing `.git` from the name. The settings hint/docs note reinstalling.
