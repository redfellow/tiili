## Why
tiili.app is 27 MB, the aarch64 DMG 9.4 MB and the updater archive 11.2 MB. Most of that comes from an untuned release build, duplicate Heynote fonts and a zlib DMG. The bundle can shrink a lot without dropping guesslang, math.js, any font family or the Nerd Font symbols.

## What Changes
- `src-tauri/Cargo.toml` gets a `[profile.release]`: `lto = true`, `codegen-units = 1`, `strip = true`, `panic = "abort"`, and an `opt-level` of `"s"` or `3`, whichever the PTY throughput measurement favours. This also shrinks tiili-cli and the Windows and Linux builds.
- `scripts/heynote.mjs` post-build deletes the `.woff` copies of Heynote's fonts and drops their `format("woff")` sources from the CSS. If Heynote's output changes shape, it fails loudly. `public/heynote/` is regenerated by the script.
- `scripts/bundle.mjs` on macOS re-converts the built DMG to ULMO (lzma) with `hdiutil convert`. When `APPLE_SIGNING_IDENTITY` is set, it re-signs the DMG. Tauri 2's bundler has no setting for the DMG format: its bundle_dmg.sh supports `--format`, but Tauri never passes it.
- Brotli compression of the embedded frontend (Tauri's default `compression` feature) is confirmed active. The updater `.app.tar.gz` stays gzip, as the Tauri updater requires.

## Assumptions
- ULMO, not ULFO: lzma is usually smallest and opens on macOS 10.15+. tiili is Apple Silicon only, so it needs macOS 11+ anyway.
- Tauri notarises and staples the .app before it makes the DMG, so the re-converted DMG only needs `codesign` again, not a new notarisation. The alternative was notarising the DMG itself, which nothing does today.
- The before and after sizes in the PR come from the implementer's local `npm run bundle`.
